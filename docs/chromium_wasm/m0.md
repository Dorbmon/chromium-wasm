# M0: reproducible primary WebAssembly toolchain

M0 turns Chromium's existing secondary Emscripten toolchain into an explicitly
gated primary toolchain and builds one standalone smoke executable. The M0 root
graph contains no V8, Content, Ozone, or Chrome UI targets.

The manifest also pins the Chromium Rust archive and checksum, Node, GN, Ninja,
the depot_tools CIPD client, depot_tools Python, immutable CIPD instances, and
installed artifact hashes. `bootstrap.py --verify-only` checks these without
installation or configuration writes and without using the network. Compiler
and linker entry points discard host `EM_*`/`EMCC_*` settings and force the
hash-checked repository emsdk configuration plus the repository-owned
`out/wasm-emscripten-cache`.

## Reproduce

Start with a normal clone of this fork on Linux x86-64. The bootstrap initializes
only the M0-required gitlinks (ANGLE, V8, and depot_tools), installs immutable GN
and Ninja packages, installs Emscripten 5.0.6, and creates the two ignored
configuration files required by the primary toolchain:

```bash
python3 tools/wasm/bootstrap.py

export PATH="$PWD/buildtools/linux64:$PWD/third_party/depot_tools:$PATH"
export XDG_CONFIG_HOME="$PWD/out/wasm-xdg"

gn gen out/wasm
autoninja -C out/wasm hello_wasm
python3 -m unittest discover -s tools/wasm/tests -p 'test_*.py' -v
python3 tools/wasm/run_node_smoke.py out/wasm/hello_wasm.js
python3 tools/wasm/run_browser_smoke.py --case hello
```

The browser runner discovers Chrome/Chromium from an explicit `--browser`,
`CHROMIUM_WASM_BROWSER`, `CHROME_PATH`, `PATH`, or a local Playwright browser
cache. It has no Playwright or Puppeteer dependency.
The host browser sandbox remains enabled by default. `--no-sandbox` is an
explicit escape hatch only for an already-isolated CI container that cannot
enable user namespaces.

After installation, verify every source and tool pin offline:

```bash
unshare --user --map-root-user --net -- \
  python3 tools/wasm/bootstrap.py --verify-only
```

`gn gen` must report a 29-target graph from 63 files. The Node runner must end
with `CHROMIUM_WASM_M0_NODE:PASS`, and the browser runner must end with
`CHROMIUM_WASM_M0_BROWSER:PASS`.

The complete sequence was also run from a fresh checkout with no initialized
M0 submodules, CIPD tools, emsdk, generated GN configuration, or output
directory. The final verification pass ran in a network namespace with no
network interfaces.

## What the smoke proves

The generated ES module uses pthreads, `PROXY_TO_PTHREAD`, a fixed pthread pool,
memory growth with an explicit 2 GiB maximum, Wasm BigInt, and an exit-capable
runtime. The C++ test proves:

- `main()` is neither the browser JavaScript thread nor Emscripten's main
  runtime thread;
- a nested C++ pthread starts and joins;
- C++20 atomic wait/notify wakes across threads;
- static construction and thread-local storage work;
- `steady_clock`, `emscripten_get_now()`, and a 250 ms sleep advance;
- stdout and stderr remain separate.

The host page contains a focusable canvas and displays the Chromium, V8,
Emscripten, and port revisions. The server returns:

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Resource-Policy: same-origin
Content-Type: application/wasm
```

The browser test requires `crossOriginIsolated`, `SharedArrayBuffer`, canvas
focus, a zero `onExit` code, separate stream sentinels, and at least three
10 ms heartbeat ticks between C++ runtime markers. It does not treat the early
Emscripten module-factory resolution as process completion.

## Measurements

Measured on 2026-07-23 with the pinned release configuration:

| Metric | Result | Method |
|---|---:|---|
| JavaScript loader size | 103,060 bytes | generated file size |
| Wasm size | 53,712 bytes | generated file size |
| Compressed Wasm size | 23,029 bytes | Python gzip level 9, deterministic timestamp |
| Link time | 354 ms median | three warm relinks, range 344–356 ms, Ninja log |
| Node startup and runtime | 297.199 ms median | three complete `onExit` runs |
| Browser C++ runtime interval | 251.18 ms | clean-checkout runtime markers in headless Chrome 149 |
| Browser heartbeat | 26 ticks | 10 ms timer during the same runtime interval |

Debug builds (`is_debug=true`, `symbol_level=2`) additionally emit
`hello_wasm.wasm.map` and `hello_wasm.wasm.debug.wasm`.

## Known limitations

- This is a build/runtime gate, not a browser. V8, Content, Ozone, networking,
  profile storage, media, and Chrome UI have not been ported.
- The loader canvas is a deterministic host-harness surface only.
- The 2 GiB maximum memory and two-worker pool are seed values for M0, not
  final browser sizing.
- Wasm remains single-process and cannot provide desktop Chromium's sandbox,
  process isolation, or Site Isolation.
